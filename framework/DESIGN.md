# 정서-욕구 아키텍처 설계 (Drive-Affect Architecture)

> 이 프로젝트의 최상위 설계 문서. 로봇은 외부 명령이 아니라 **내부 욕구(고통/행복)에 의해
> 행동을 선택**하는 동물형 에이전트를 지향한다. framework/ 모듈은 모두 이 문서를 구현한다.

## 전체 구조 (2층 + 조절층)

```
[호르몬 층 Hormones]  ← 같은 상황을 "다르게 느끼게" 하는 조절자 (성격/기분)
        │ 변조
        ▼
[상위: 욕구/정서 층 Drive Layer]
  내수용감각(에너지·손상·독성·피로) → 고통 계산 → 쾌/불쾌 보상
  매니저 정책: 0.5~2초마다 스킬 선택 (처음엔 규칙 기반 → 나중에 RL 교체)
        │ 스킬 호출
        ▼
[하위: 요소행동 층 Skill Layer]
  걷기/뛰기/회전/휴식 등 — 각각 인위적 보상(tasks/)으로 독립 학습 후 동결(freeze)
  10ms 단위 관절 토크 출력
```

핵심 원칙:
- **요소행동은 욕구와 무관하게 학습**한다 (인위적 보상 사용, 지금의 forward_locomotion 방식).
- **욕구 층만 쾌/불쾌 보상으로 학습**한다. 스킬은 동결된 채 재사용 → 비정상성 문제 회피.
- 새 욕구가 생겨도 걷기를 재학습하지 않는다 (재사용성).

## 운동제어 3층 구조 (대뇌-소뇌-근육 모델)

인간의 운동제어를 본뜬 구조. 자동화된 절차(소뇌)는 싸고 빠르며, 대뇌의 개입/직접제어는
범용적이지만 비싸다. 에너지 고통이 자동화를 "원하게" 만드는 압력으로 작동한다.

```
[대뇌 Cortex — 느림, 범용, 비쌈]
  의도: 매니저가 레퍼토리에서 스킬 선택 + 파라미터        → skill_manager
  개입: 실행 중인 스킬 출력에 잔차(residual) 보정을 더함    → residual.py
        개입 크기에 비례한 "주의 비용"을 고통에 가산
        → 평소 잔차≈0(소뇌에 맡김), 필요할 때만 개입이 창발
  직접제어: 레퍼토리에 없는 상황은 모델 기반 계획(MPPI)으로  → (향후) cortex_mpc.py
        매 스텝 무거운 연산 = 높은 에너지 비용, 어색하지만 무엇이든 시도 가능
[소뇌 Cerebellum — 빠름, 특화, 쌈]
  레퍼토리: 동결된 스킬 정책들                            → skill_registry.py
  통합(증류): 대뇌 직접제어의 성공 궤적을 모방학습(BC)으로
        압축해 새 스킬로 등록 → 레퍼토리 성장. "연습하면 자동화된다"
[근육 Muscle]
  위치서보/텐던 (don2.xml)
```

## 발달 커리큘럼 — 스킬 계보(lineage)

아기의 운동 발달처럼 큰 근육의 단순한 움직임부터 배우고, 파생 스킬은 부모 스킬의
체크포인트에서 **워름스타트**한다. 스킬마다 계보(parent)를 skill_registry에 기록한다.

```
stand (기립 균형, 뿌리)
 └─ walk (저속 보행) ← stand에서 워름스타트
     ├─ sprint      ←┐
     ├─ turn_left   ←┤ walk에서 워름스타트 (걸음 스타일 계승)
     └─ turn_right  ←┘
toe_curl (소근육, 별도 계보 — 자세·역학이 달라 이식 무익)
```

규칙:
- **변형 스킬은 워름스타트가 기본** (부모의 PPO 가중치 + VecNormalize 통계 함께 승계 —
  통계를 빼먹으면 관측 스케일이 어긋나 승계 효과가 무너진다).
- **"기존+α" 스킬(거친 지형 걷기 등)은 잔차 방식**: 부모는 동결, 잔차망만 학습.
- 자세/역학이 근본적으로 다른 스킬(누워서 하는 동작 등)은 처음부터 학습이 맞다.
- 몸(로봇 XML)이 바뀌면 그 몸에서 학습한 세대(generation)를 명시하고 계보를 다시 딴다
  (gen3 = v3 발 + 내수용감각 157 통일).

## 합성층(SkillComposer) — "학습은 악보를 쓰는 상위단만" 원칙

스킬은 악보(최적화된 기록)다: 모듈화되고, 결합되고, 오버로드되고, 재사용된다.
**프리미티브 세트가 완성된 뒤로는 전체 네트워크 학습을 금지**하고(예외: 몸이 바뀐
세대 교체 시의 프리미티브 재구축), 새 운동은 아래 합성 구조로만 만든다:

```
[학습 대상 — 소형 상위망 하나]
  π_upper(관측) → (혼합 가중치 w[K], 소형 잔차 r)
[동결 — 재학습 금지]
  최종행동 = Σ wᵢ·베이스ᵢ(관측) + α·r     (잔차에는 주의 비용 부과)
```
- **결합**: walk+turn_left 혼합 → 곡선 주행처럼, 동시 합성으로 새 운동이 성립
- **오버로드**: 혼합으로 부족한 부분만 잔차가 보정 (residual.py의 주의 비용 그대로)
- **재귀적 모듈화(증류)**: 합성 스킬이 쓸만해지면 BC로 단일 소형망에 증류해
  새 악보로 레지스트리에 등록 → 다음 합성의 베이스가 됨. 소뇌 통합과 동일 파이프라인.
- 워름스타트 계보는 "첫 악보집(프리미티브 세트)을 만드는 과도기 도구"로 한정한다.
- 구현: framework/composer.py (계획) — ComposerEnv: 동결 베이스 K개 로드,
  행동공간 = [w 로짓 K + 잔차 n_act], 관측은 베이스와 동일.

## 고통 (Pain)

내부상태마다 항상성 목표점(setpoint)을 두고, 위험 방향 편차의 가중합:

```
pain = Σ wᵢ(H) · deviationᵢ²
  - 에너지 고갈:     battery가 setpoint 이하로 내려간 정도
  - 에너지 급소모:   전력(τ·ω/효율) 스파이크
  - 강한 충격:       IMU 가속도 스파이크
  - 위험물질 접촉:   독성(toxicity) 내부상태 (worlds/fields 화학 필드에서 유입)
```
- 가중치 wᵢ는 호르몬에 의해 변조됨 (아래).
- pain과 그 구성요소는 **반드시 관측에 포함**(내수용감각) — 느껴야 행동으로 연결된다.

## 행복 (Pleasure) — 전위 기반(potential-based) 정의 (중요)

```
reward(t) = Pain(t-1) − Pain(t)  +  인위적 쾌락 이벤트(t)
```
- "고통의 급격한 해소 = 행복"을 차분 형태로 구현. **차분 형태여야 하는 이유**:
  자해 루프(일부러 고통을 만들고 해소해서 보상 수확) 시 생성 벌점과 해소 보상이
  정확히 상쇄되어 순이익 0 → reward hacking 원천 차단.
- 인위적 쾌락(고급 먹이의 "맛" 등)은 별도 항. 반드시 **습관화(satiation)** 적용:
  같은 자극 반복 시 효과 지수 감소 → 쾌락 소스 앞 무한 반복(중독 루프) 방지.

## 호르몬 층 (Hormones) — 조절자

내부상태가 "무엇이 부족한가"라면, 호르몬은 **같은 부족을 어떻게 느끼고 반응할지 바꾸는 계수**.
동일 환경·동일 정책에서도 다른 행동을 만들어내는 원천.

작동 경로 3가지:
1. **관측 포함** → 정책이 호르몬 수치에 조건부로 행동
2. **쾌/불쾌 가중치 변조** → 같은 사건이 더/덜 아프게 느껴짐
3. **물리 파라미터 변조** → 몸 자체가 달라짐 (예: 토크 한계)

| 호르몬 | 분비 조건 | 감쇠 | 효과 |
|---|---|---|---|
| 아드레날린 | 급성 위협(강충격, 위험 급접근) | 빠름(수초) | 토크한계 +30%, 에너지소모 ×1.5, 일시 진통(pain 가중↓), 매니저 반응주기 단축 |
| 코르티솔 | 고통의 반복/지속 누적 | 매우 느림(수분) | 공포 민감도↑, 탐색성↓, 휴식욕구↑, 만성 고농도 시 에너지 효율 저하 |
| 도파민형 | 예상 밖 쾌락, 새로운 자극 | 중간 | 쾌락 민감도↑, 탐색성↑, 신규 오브젝트 접근 성향 |
| 세로토닌형 | 욕구 충족 상태 지속 | 느림 | pain 가중 완화, 안정/휴식 선호 |

구현 규칙:
- 호르몬 = 벡터 H, 각 성분은 [0,1]. 동역학: 이벤트 트리거 분비 + 지수 감쇠 + 포화.
- **개체 기질(성격)**: 호르몬별 기저치·분비계수를 개체 프로필로 분리.
  학습 시 프로필 랜덤화 → 겁많은/대담한/활동적 개체가 같은 정책에서 분화.
- Date/시간 의존 없음 — 모든 동역학은 시뮬레이션 스텝 기준.

## 월드 콘텐츠 규약 — "감각 없는 보상/위험 금지"

**쾌/불쾌와 연결된 모든 오브젝트·지역은 원거리 감지 가능한 감각 시그니처(냄새/빛)를
최소 1개 가져야 한다.** 없으면 부딪혀야만 아는 세계가 되어 접근/회피 학습이 불가능하다.

### 감각 예고 3층 체계
```
원거리: 냄새(퍼짐), 빛(발광체)              ← "저쪽에 뭔가 있다"
근거리: 바닥 색/명암, 전방 rangefinder      ← "이 구역에 들어왔다 / 곧 들어간다"
접촉:   마찰/요철/푹신함(물리), 터치, 독성  ← "지금 겪고 있다"
```

가상 센서 고정 슬롯 (관측 차원 불변 원칙, worlds/README.md 참조):
- **냄새**: 3채널 "냄새 공간" × 콧구멍 2개(몸 전방 좌/우) = 6슬롯. 좌우 차로 방향 감지.
- **빛**: 밝기 + 색상 = 2슬롯.
- **바닥 시그니처**: 로봇 바로 아래 바닥의 [밝기, 색상] = 2슬롯.
  구현은 zone map 조회 방식(`terrain.zone_at(xy)`) — 실물로는 배 밑 RGB/반사율 센서
  (TCS34725류, 라인트레이서용)를 모사. 나중에 mujoco.Renderer 초소형 하향 카메라(4×4px)로
  교체 가능(인터페이스 동일, 렌더링 비용 때문에 초기엔 zone 조회 권장).
- **전방 바닥 거리**: `rangefinder` 2개를 전방 아래로 비스듬히 — 요철/낭떠러지를 밟기 전 감지
  (실물: IR 절벽감지 센서, 로봇청소기 방식) = 2슬롯.
- 필드/구역 정보 없는 월드에서는 0 채움.

### 지형 구역(Zone) 규약 — 물리와 시각을 묶어 "구역의 정체성"을 만든다
지형은 단일 plane이 아니라 **구역별 타일 geom**(얇은 box) 또는 hfield로 구성하고,
구역마다 물리+시각 속성을 세트로 부여한다:
- 마찰(`friction`): 미끄러운 늪 ↔ 단단한 초원 — 물리로 직접 체감됨
- 편평도(hfield 거칠기): 발 터치 불규칙 + IMU 흔들림으로 체감
- 푹신함(`solref/solimp`): 모래밭처럼 무른 바닥
- 색/명암(`material`/`rgba`): 바닥 시그니처 센서로 감지 — 보상/고통의 근거리 예측 단서
예: 독성 늪 = 어두운 붉은색+미끄럽+푹신+C냄새 / 먹이 초원 = 밝은 초록+평평+단단.
terrain 폴더에는 XML과 함께 zone map(파이썬/yaml)을 쌍으로 둔다.

### 먹이 카탈로그 (변별 학습이 과제가 되도록 냄새 설계)
| 먹이 | 에너지 | 기타 | 냄새 | 희소성 |
|---|---|---|---|---|
| 기본 사료 | 중간 | — | A채널 강함 | 흔함 |
| 고에너지 열매 | 높음 | +인위적 쾌락 | B채널 강함 | 희귀 |
| 독성 먹이 | 소량 | 독성 고통 | **B채널 유사 + C채널 미량** (의태) | 중간 |

### 위험 지역 카탈로그
- 독성 웅덩이: 접촉 시 toxicity 누적, C채널 냄새 강함
- 방전 지대: 배터리 급감, 붉은 빛
- 충격 위험물: 움직이는 진자/롤러 (아드레날린 트리거)

### 시간 변동 (코르티솔·세로토닌이 의미를 가지려면 필수)
- 낮/밤 주기: 전역 광량 변화, 충전소 발광이 밤에 더 두드러짐
- 먹이 리스폰/고갈 주기, 계절적 희소성

## 월드 프리셋 로드맵 (단계별 검증)
1. `nursery` — 평지 + 충전소 1 (욕구→행동 배관 검증)
2. `meadow` — 먹이 2종 + 냄새 필드 (냄새 추적 학습)
3. `hazard_valley` — 독성 먹이/웅덩이 (B vs B+C 냄새 변별, 회피)
4. `diurnal_world` — 낮/밤 + 희소성 (장기 전략, 휴식 타이밍)

## 구현 모듈 매핑 (framework/)
- `interoception.py` — 내부상태 + setpoint + 편차 계산 (구 internal_state 계획을 대체)
- `affect.py` — pain 가중합(호르몬 변조 포함), 전위 기반 보상, 습관화
- `hormones.py` — 호르몬 동역학 + 개체 프로필 + 변조 인터페이스
- `skill_manager.py` — 스킬 레지스트리 + 매니저 (규칙 기반 우선, RL 교체 가능 구조)
- 나머지 모듈(compose, base_env 등)은 framework/README.md 표 참조

## 구현 순서 (권장)
1. mjcf_compose + base_env (물리 배관)
2. interoception + 배터리 하나로 nursery 검증 (규칙 기반 매니저)
3. affect(고통/행복) 도입, foraging 학습
4. fields(냄새/빛) + meadow
5. hormones + hazard_valley
6. diurnal + 개체 프로필 랜덤화
