# 실증 교훈 모음 — 제작하며 직접 확인한 것들

> 새 작업 전에 훑어볼 것. 각 항목: 무엇을 겪었나 → 왜 그런가 → 규칙.

## 학습 설계

**1. 길항 관계 워름스타트는 해롭다 (가장 중요한 발견)**
stand에서 워름스타트한 walk가 2세대 연속 "서있기 국소최적"에 갇혔다
(gen1 스크래치 717=진짜 보행 vs gen2 479/gen3 449=서있기 보상 이론값과 일치).
부모의 "움직이지 마라" 습관이 탐험을 죽였기 때문. 반면 walk→turn은 초반 수렴이
5배 빨랐다(10만 스텝에 gen1의 50만 스텝 수준). **규칙: 부모 행동이 자식 과제의
구성요소면 워름스타트, 부모 습관을 깨야 하면 스크래치.**

**2. 워름스타트는 VecNormalize 통계도 함께 승계해야 한다**
PPO 가중치만 옮기면 관측 정규화 스케일이 어긋나 승계 효과가 무너진다.
`VecNormalize.load(부모.pkl, 새 env)` + `training=True`로 이어야 함.

**3. 흐름(rate) 고통은 직접 비용, 상태 고통은 전위 차분**
전력 소비를 전위 차분으로 보상화하면 일정하게 낭비할 때 기울기가 0이 되어
절약을 학습하지 못한다. 반대로 상태 고통(저SoC, 손상)을 직접 비용으로 주면
"일부러 아프게 한 뒤 해소해서 보상 수확"하는 자해 루프가 열린다.
**흐름=스텝당 직접 차감, 상태=pain(t-1)−pain(t).** (affect.py에 구현)

**4. 에너지 고통은 행동을 실제로 바꾼다**
에너지 고통 없는 gen1 sprint는 300~500W로 3m/s 질주. 에너지 고통 도입 후
sprint는 스스로 절제된 속도로 타협했다. 별도 속도 제한 규칙 없이 내부 경제만으로.

**5. 초기 내부상태 랜덤화 필요**
SoC를 0.25~1.0 랜덤 시작시키지 않으면 정책이 저에너지 고통을 경험하지 못해
그 상황의 행동을 배울 수 없다 (domain randomization의 내부상태 버전).

**6. 관측 차원 변경 = 전 스킬 재학습**
센서/내부상태를 관측에 추가하면 기존 체크포인트 전부 무효. 대응책 둘:
① 필드/오브젝트류는 percept 전용으로 (스킬 관측에 안 넣음 — 재학습 회피, 현재 채택)
② 신경망 이식(net surgery: 새 입력 가중치 0 초기화)으로 파인튜닝 — 대규모에서 유효.

## MuJoCo/물리

**7. 충격 감지는 서브스텝 피크 샘플링으로**
env 스텝(10ms) 끝에서 한 번 읽으면 밀리초 충격 스파이크를 놓친다.
mj_step마다 가속도 피크를 추적할 것. 임계값 50m/s²면 정상 보행 착지(15~35)는
안 아프고 추락/충돌만 잡힌다.

**8. 텐던 구동은 모멘트암·스프링 균형 검증 필수**
초기 발가락: 스프링 0.25N·m/rad vs 텐던 모멘트암 7mm → 5N 당겨도 6도밖에 안 굽음.
스프링 0.08 + 모멘트암 10mm + 장력 30N으로 수정 후 정상. **텐던 설계는 항상
"장력×모멘트암 vs 스프링×각도" 수지를 계산하고 무중력 당김 테스트로 검증.**

**9. MuJoCo 뷰어 key_callback은 내장 단축키를 대체하지 않는다 (병행 발동)**
숫자 0~5는 geom 그룹 토글, L은 Convex Hull 등 다수 알파벳이 시각화 플래그.
커스텀 키는 6~9와 R처럼 미사용 키만. (실제로 L 눌러 로봇 색이 바뀌는 사고 있었음)

**10. 위치서보(position actuator)가 토크 모터보다 학습이 쉽다**
don1(토크+수동 PD)보다 don2(위치서보=실물 Dynamixel 방식)가 훨씬 빨리 안정 수렴.
행동공간을 "목표 관절각"으로 두는 것이 사실적이기도 하고 학습에도 유리.

**11. 아드레날린 토크 부스트는 model.actuator_forcerange 직접 변조로 구현 가능**
매 스텝 `model.actuator_forcerange[ids] = base * gain` — 정상 작동 확인(4.1→4.8N·m).
model 필드는 env 인스턴스별 사본이라 안전.

## 코드 함정

**12. mode를 동적으로 바꾸는 env는 생성 시점 고정값을 조심**
인터랙티브 뷰어에서 스킬 전환 시 env.mode만 바꿨더니 reset()이
`action_space.shape`(생성 시점 고정)로 `_prev_action`을 만들어 브로드캐스트 크래시.
**mode 의존 크기는 항상 현재 mode에서 유도할 것.**

**13. Windows 한글 경로에서 MuJoCo from_xml_path 실패**
`ParseXML: Error opening file`. 파이썬 open()은 정상이므로
**상대경로 사용 또는 open()+from_xml_string 우회.**

**14. 뷰어 백그라운드 실행은 `& + 로그 리다이렉트`로**
Claude Code의 run_in_background는 뷰어 프로세스에서 조기 완료 오탐이 있었다.
확인은 PowerShell `Get-Process python | select Id, MainWindowTitle` (창 제목 = 모델명).

**15. .gitignore 하위 폴더 패턴**
`models/*_steps.zip`은 직속만 매칭. 하위 폴더는 `models/**/*_steps.zip` 필요.
(중간 체크포인트 40개가 커밋된 사고 있었음)

**16. cp949 콘솔에서 한글/특수문자 출력 깨짐**
동작에는 무해. 단 `≈` 같은 문자는 UnicodeEncodeError를 낼 수 있으니 로그 출력엔 ASCII 대체.

## 프로세스

**17. 새 로봇/부품은 학습 전에 뷰어 육안 검증**
XML → validate(헤드리스: 질량/텐던 방향/기립) → pose_test(뷰어) → env → 학습.
잘못된 지오메트리로 학습 돌리고 나서 발견하면 시간 손실이 크다.

**18. 몸을 바꾸면 그 몸으로 학습 중인 프로세스는 이미 메모리에 구 모델을 들고 있다**
XML 수정 후에는 해당 스킬 학습을 재시작해야 새 몸이 반영된다 (toe_curl을 두 번
재시작한 이유). 학습 시작 시점의 몸 세대를 커밋 로그에 남길 것.
